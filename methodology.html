본 문서는 방법론과 엔지니어링 접근만 다룬다. 특정 제품의 우회 코드·오프셋·고객 데이터는 포함하지 않는다. 모든 분석은 인가된 보안 평가 또는 공인 CTF 환경에서 수행되었다. → 윤리·인가 고지

개요

상용 RASP·안티치트가 적용된 모바일 애플리케이션의 탐지 로직을 분석할 때, 산출물의 가치는 "우회 성공 여부"가 아니라 결론의 정확도에서 나온다. 분석 결과를 방어 설계에 쓰려면, 어디까지가 런타임 실측이고 어디부터가 정적 추정인지가 명확히 구분되어야 한다.

본 문서는 그 요구를 반복 가능하게 충족하기 위해 구축한 세 가지 체계를 기술한다 — (1) 분석을 병렬화하는 멀티에이전트 하네스, (2) 모든 결론을 실측 기준으로 게이트하는 판단 규율, (3) 분석 결과를 구조화해 다음 분석에 재사용하는 지식 베이스.

2. 멀티에이전트 분석 하네스

분석을 역할별 에이전트로 분리하고, 종합·검증 단계를 삽입하여 단일 파이프라인으로 구성한다. 각 에이전트는 전용 분석 인터페이스(디컴파일러·디스어셈블러·동적 계측)를 직접 호출한다.

2.1 병렬 분석 (Java ∥ Native)

Java 계층과 Native 계층은 상이한 도구·관점을 요구하므로 동시에 분석한다. Java 레인은 난독화된 디컴파일 결과에서 탐지·종료 funnel을 추적하고, Native 레인은 공용 라이브러리를 제외한 커스텀 .so의 JNI 진입점과 탐지 루틴을 리버싱한다.

2.2 리더 종합 (상관분석)

두 계층의 결과를 교차 검증한다. Java에서 식별된 탐지 콜백이 Native의 어느 함수로 연결되는지, Native의 self-kill이 Java의 어느 핸들러를 경유하는지를 연결한다. 연결이 비는 경우 해당 분석가에게 구체적 공백을 되돌려 재분석을 지시하고 다시 취합한다.

2.3 동적 검증 (Frida)

정적 분석이 지목한 "의심 함수"는 가설이다. Frida 후킹으로 해당 함수의 실제 발동 여부와 반환값 조작에 따른 동작 변화를 런타임에서 확인한 것만 탐지 로직으로 인정한다.

2.4 반대자 천장 게이트

파이프라인의 안전장치로, 모든 부정 결론을 독립적으로 재검증한다. 상세는 3.5절.

3. 판단 규율 — 결론 게이트 다섯 원칙

본 체계의 핵심은 자동화가 아니라 규율이다. 반복 관찰된 오판 유형을 성문 체크리스트로 정리하여 모든 결론에 적용한다.

3.1 "불가/천장"은 결과가 아니라 가설이다

"userspace로는 불가", "커널에서만 차단" 등 부정 결론(이른바 '천장' — 더는 못 뚫는다는 한계 주장)은 그 자체로 증명을 요한다. 확정 기록은 세 조건을 모두 충족할 때만 허용된다 — (1) 결정 코드의 화이트박스 판독(preimage), (2) userspace 개입 지점 부재 확인(소거 완전성), (3) 도구 A/B를 통한 관측자 효과(내 분석 도구가 결과를 바꾸는 현상) 배제. 미충족 시 결론은 "미규명"으로 격하한다.

사례(익명화). 어느 인증 솔루션 분석에서 프로세스가 반복 조기 종료되자 "커널 레벨 방어로 우회 불가"라고 3회 연속 단정하였다. 실제 원인은 계측 도구가 노출한 스레드 이름을 솔루션이 스캔하여 self-kill한 것이었고, 스레드 이름을 은닉하자 생존하였다. 커널은 관여하지 않았다.

3.2 관측자 효과를 먼저 배제한다

크래시·조기 종료를 타깃 방어로 귀속하기 전에, 계측(Interceptor/훅)을 제거한 A/B를 선행한다. 공존이 목표인 경우 결정 지점까지는 순수 데이터 write(byte-patch)만 사용하여 훅의 부작용을 차단한다. "훅을 걸자 종료되었다"는 훅 자체가 종료를 유발했을 가능성을 배제하기 전까지 증거가 아니다.

3.3 정적 경로의 존재는 런타임 사용을 의미하지 않는다

디컴파일 결과에 탐지·종료 로직이 보이더라도 실제 발동 여부는 별개다. 런타임 발동선(trigger)을 확인하기 전까지 "해당 탐지가 동작한다"고 단정하지 않는다.

3.4 긍정 결론도 동일하게 게이트한다 (양방향 규율)

부정 결론뿐 아니라 "서버가 검증한다", "이 값은 화면 표시용 복제본일 뿐이다(미러)", "이 값의 최종 결정권은 X에 있다" 같은 긍정적 메커니즘 판정도 실측 없이 단정하지 않는다. 정적 코드 판독만으로 런타임 동작을 확정하는 것을 금지한다.

사례(익명화). 어느 게임의 전투값 분석에서 서버 동기화 핸들러의 코드상 존재를 근거로 "HP는 서버 권위 확정"이라 기록하였다. 그러나 런타임에서 해당 핸들러는 전투 중 0회 발동하였고, 클라이언트 저장값을 전 계층 조작해도 결과가 불변이었다. "저장값 비권위"는 실측되었으나 "서버 권위"는 미확보이므로 결론을 "미규명"으로 하향하였다. 추적되는 값이 곧 권위 있는 값은 아니며, write A/B만이 증거가 된다.

3.5 반대자가 모든 부정 결론에 서명한다

분석 주체는 자기 가설을 확증하는 경향이 있으므로, 파이프라인에 상설 반대자 역할을 두어 모든 "불가/천장" 결론을 공격적으로 재검증한다. 반대자는 preimage·소거완전성·도구 A/B·사전편향 체크리스트로 결론을 심사하고, 통과한 것만 "천장 카드"로 서명한다. 서명 없는 부정 결론은 리포트에 확정으로 기재하지 않는다. 작성과 검토는 항상 분리된 레인에서 수행되며, 분석 주체가 자기 결론을 자기가 승인하지 않는다.

4. 축적된 분석 지식의 재활용

분석 결과를 일회성 리포트로 소비하지 않고, 구조화된 지식 단위로 기록하여 다음 분석의 출발점으로 재사용한다. 타깃마다 처음부터 재도출하지 않는 것이 본 체계가 시간이 지날수록 빨라지는 이유다.

유형내용예
타깃 기록특정 앱/솔루션의 보호 구성·탐지 벡터·우회 경로"A 앱: 종료 벡터 = 스레드명 스캔, 생존 조건 = 스레드명 은닉"
재사용 기법타깃 비종속적 분석 기술"자가삭제 모듈은 unlink 후킹으로 보존"
판단 교훈과거 오판과 그 원인, 재발 방지 규칙"조기 크래시를 커널로 단정 금지 → 계측 A/B 선행"
환경 gotcha도구·플랫폼의 반복적 함정특정 프레임워크 버전의 API 변경, 실행 환경 제약

교차 타깃 전이. 동일 계열 솔루션은 방어 메커니즘을 공유하는 경우가 많다. 한 타깃에서 검증된 사실은 동일 계열의 새 타깃에서 재검증 없이 가설의 출발점으로 활용된다. 단, 전이된 지식은 가설이지 사실이 아니다 — 새 타깃에서 반드시 재검증(발동선 A/B, 프로세스 맵 확인)을 거친다. 지식 재활용은 분석 속도를 높이되 판단 규율을 우회하지 않는다.

재현성. 휘발성 값(세션별 주소·PID 종속 포인터)이 아니라 재도출 절차와 불변 관계를 기록한다. 예컨대 특정 필드를 "주소 0x…"가 아니라 "엔티티 베이스 + 고정 오프셋, 재도출 레시피 X" 형태로 남겨, 다른 세션·빌드에서도 복원 가능하게 한다.

5. 적용 기술 사례 (비무기화)

규율과 자동화·지식 재활용을 결합한 결과 정리된 재사용 기법의 일부다. 방법 수준의 요약이며 구체 페이로드·오프셋은 생략한다.

  • 자가삭제 모듈 복구. 탐지 후 자신을 unlink하는 보안 모듈을 /proc/[pid]/maps의 삭제 흔적으로 식별한 뒤 unlink 후킹으로 삭제를 차단하여 메모리에서 보존하고 정적 분석으로 복원한다. → 사례 보기
  • 암호화된 탐지 함수의 런타임 복원. JNI 진입점이 비어 보이는(실행 시 복호화되는) .so는 로드 시점의 메모리 덤프로 복호화된 코드를 추출하여 분석 가능 상태로 만든다. → 사례 보기
  • IL2CPP 전투값 역추적(값 기반). 함수·필드명이 런타임에서도 암호화된 커스텀 IL2CPP 환경에서, 난독화되지 않는 데이터 값(HP·전투력)을 앵커로 값 스캔 → 변화 추적 → 소유 객체 그래프 climb으로 엔티티 구조를 복원한다. 조작 가능성·권위 소재는 3.4 규율에 따라 "미규명"까지 엄격히 구분해 기록한다.
  • 다층 복호화 체인 역산(CTF). 공인 CTF 환경에서 Java 난독화 → XOR 문자열 복호 → AES 에셋 복호 → 네이티브 .so → 최종 dex로 이어지는 다단계 보호를, 각 단계의 복호 루틴을 재구현하여 끝까지 역산한다. → 사례 보기

6. 결과

  • 거짓 천장 감소. "불가"로 단정되었다가 뒤집힌 사례들을 규율이 사전 차단하면서 부정 결론의 신뢰도가 향상된다.
  • "미규명"의 명시. 증적 없는 결론을 "확정"으로 포장하지 않는다. 미규명은 실패가 아니라 정직한 경계 표시이며, 방어팀에 "추가 정밀 검증이 필요한 지점"을 정확히 지시한다.
  • 분석 가속. 지식 베이스의 누적으로 신규 타깃의 초기 정찰·오판 회피 비용이 지속적으로 감소한다.
  • 재현 가능한 산출물. 휘발성 값이 아닌 재도출 절차가 남아 세션·분석가 교체에도 결과가 보존된다.
